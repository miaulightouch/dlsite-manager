# Launcher export

Linux-only action that adds a downloaded work to Steam, Faugus Launcher or Heroic
so it can run through a Proton build chosen by the user.

## Boundaries

- `crates/dm-launcher-export` owns discovery, formats and file safety. It takes an
  `ExportEnv` (home, XDG folders, `/proc` root), so tests run against temp fixtures.
- `src-tauri/src/launcher_export.rs` only resolves the work from the library,
  enforces the existing library-root check, and writes an audit event.
- The frontend sends a work id and an install id, never a launcher file path. The
  crate re-discovers installs and refuses ids it did not find.
- The crate builds everywhere. `is_supported()` is false off Linux, the command
  refuses, and the UI does not show the action.

## File safety

Every launcher computes all of its new file contents before anything is written.
A file that fails to parse fails that launcher only and is left alone. Writes then
go: compare (no change means no write and no backup), confirm the file did not
change since it was read, timestamped backup beside the file, temp file in the same
folder, fsync, rename. A failure part-way through a launcher's files restores the
ones already written.

Binary VDF keeps value types and order, so untouched data round-trips byte for
byte. `config.vdf` is edited by byte span, so everything outside the changed
mapping is unchanged. JSON keeps key order through `preserve_order`.

## Identity and prefixes

- Steam: a shortcut whose `Exe` is inside the work's folder belongs to that work.
  Its stored `appid` is kept on update, so the tool mapping and artwork stay
  attached even when the name or executable changes.
- Faugus: `gameid` is `dlsite-<work id>`. Heroic: `app_name` is `dlsite-<work id>`.
- The default prefix is `~/Games/dlsite-manager/prefixes/<work id>`. The form starts
  from the value in an earlier export so a re-export cannot silently switch prefixes.
  Prefixes inside the work's folder are refused because re-downloading replaces that
  folder. Nothing in this feature deletes a prefix.
- Steam has no per-shortcut prefix field; the prefix is set by
  `STEAM_COMPAT_DATA_PATH='<prefix>'` in `LaunchOptions`, merged with the user's options.
- Heroic and Faugus use the same folder as `winePrefix` and `prefix`.

## Format sources

Checked against source on 2026-11-07, Faugus `63d71a1`, Heroic `4737fdb`:

- Faugus `faugus/path_manager.py` (paths, legacy migration), `faugus/utils.py`
  (`GAME_FIELDS`, `prepare_game_kwargs`), `faugus/runner.py` (runner resolution).
- Heroic `src/backend/storeManagers/sideload/` (library), `src/backend/game_config.ts`
  and `src/common/types.ts` (settings), `src/backend/launcher.ts` (proton environment),
  `src/backend/shortcuts/nonesteamgame/` (Steam `appid`, running-Steam behavior).
- Steam: Valve does not document these files. The `appid` formula matches both Faugus
  and Heroic; the mapping entry matches ProtonUp-Qt `pupgui2/steamutil.py`; bundled
  Proton ids follow third-party tools (Steam ROM Manager, Vortex).

Inferred, not read from source: Flatpak paths for Faugus and Heroic data, from the
Flatpak XDG convention; and Steam honoring `STEAM_COMPAT_DATA_PATH` from launch options.
